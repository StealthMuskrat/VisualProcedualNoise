## Windows and release acceptance

GitHub verification is introduced after the implementation batches. The Windows job checks JVM contracts, builds an x64 app image with its own Java runtime and verifies packaged resources/native loading, guide/shader copies, acceptance evidence and its GPU-independent reader. Windows review checks also reject a directory junction without modifying its target. A hosted runner may retain a truthful blocked GPU result; the packaging check requires the correct report/status and never converts that result to hardware acceptance. A hosted runner does not establish the application's GPU performance or desktop behavior.

Use the [packaged acceptance guide](WINDOWS_ACCEPTANCE.md) to retain build/device identity, smoke/fullhd results and manual observations. Before public release, run the specification's matrix on physical Windows machines: NVIDIA, AMD and Intel drivers; clean account without Java; Unicode/spaced paths; DPI and monitor changes; fullscreen; focus loss; minimize/restore; long sessions; repeated quality changes; still/sequence color and orientation; and practical performance targets. Record the actual Windows versions and hardware before declaring support.

The installed Linux script launcher was exercised with replay exports. A native Linux app image was built, but its launcher could not be validated in this sandbox because the process filesystem is unavailable. Linux app images are outside the Windows distribution target.
